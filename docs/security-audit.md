# Security audit (Slice 3, rebased baseline)

## Scope and classification

Reviewed the frozen spec (`SLICE_3_SPEC.md`), project rules (`AGENTS.md`), schema/functions/policies, and merged frontend (`src/main.js`, `src/supabase.js`). Status labels below distinguish merged frontend/spec work from the still-pending database RPC implementation; the SQL scripts present in this worktree do not yet define `create_booking` (`database/02_functions.sql:1-68`).

The frontend calls these tables: `profiles`, `packages`, `food_categories`, `food_items`, `package_food_items`, `package_categories`, `bookings`, `booking_food_items`, `booking_cancellation_requests`, and `notifications` (`src/main.js:130,207,226,234,243,246,256,286,288,330,374,611,706,790,795,859,960,1058,1098,1115,1131,1165,1206,1223,1413,1456,1479,1482,1577,1599,1634,1650,1673,1677,1741,1759,1886,1921,1937`; line numbers are from the audit baseline and some later calls shifted in the merged frontend). The declared schema tables have RLS and policies in `database/03_policies.sql:2-46`; `notifications` and `booking_cancellation_requests` are not created or covered in the supplied SQL. The merged frontend calls the cancellation review RPC (`src/main.js:1383-1389` in the baseline) but it is outside Slice 3 scope (`SLICE_3_SPEC.md:404-410`).

## Slice 3 disposition

The merged frontend resolves the client-side write path: it sends only input fields and selected item IDs, keeps the price calculation display-only, and invokes `create_booking` (`src/main.js:337-343`; contract `SLICE_3_SPEC.md:386-397`). This does not establish server-side pricing, atomicity, or secure reference generation until the database worker's RPC is present and verified; those are classified **(b) pending slice3-db RPC**. Missing notifications/cancellation database support and the admin search filter remain **(c) open**, with cancellation explicitly outside this slice (`SLICE_3_SPEC.md:404-410`).
